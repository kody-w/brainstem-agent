# M0 offline contract

This is the contract of the offline fixture harness, the first layer of the
runtime. The running product (real Grail workers, sandbox, tools, daemon) is
specified in [`cell.md`](cell.md); the modules below are shared with it, and
their offline fixtures remain valid unit evidence.

The harness itself is **not a running Grail host**, a sandbox or an activated
RAPP estate. No Grail source is copied or executed by it. It uses explicitly
synthetic authority and injected fixture transports and refuses live mode.
Grail files and live inference functions are never changed.

## Modules

- `adapter.py`: pure core request/response/SSE contract normalization.
- `state.py`: one transactional SQLite store for chat, jobs, and synthetic grants.
- `policy.py`: synthetic grant binding, expiry, revocation, and generation checks.
- `harness.py`: headless fixture orchestration; explicitly not a provider client.
- `__main__.py`: offline smoke/qualification report only; no real model calls.

Use Python 3.11+, standard library only, with `unittest`. The public APIs below
are the shared contract of these modules. Fixtures use temporary private
directories. Never access `~/.brainstem`, real account stores, or port 7071.

## Adapter

`CoreContractError` is the explicit refusal/error type.

`build_core_request(user_input, session_id, history)` returns the existing core
request keys `user_input`, `session_id`, `conversation_history`. Input text and
session ID must be nonempty strings. History accepts only user/assistant/tool
roles with string content; no system messages. Enforce configurable bounded
text/history limits with conservative defaults; reject malformed input.

`normalize_core_response(payload, expected_session_id)` returns **exactly**
`response` (string), `agent_logs` (list of strings), `session_id` (string).
Validate the expected session binding. Error-shaped HTTP 200 (including
`no_copilot_access`) is not success. Split flat core logs deterministically
into bounded lines; preserve list logs only when every item is a string.
Redact known credential-shaped assignments and bearer values without claiming
universal secret detection. Strip extra core metadata. Empty answers, missing
required fields and oversize values refuse.

`normalize_sse(chunks, expected_session_id)` accepts an iterable of text chunks
and returns the normalized terminal `done` response. Handle chunk splits,
CRLF, comments, and bounded frames/total bytes. Error events, malformed JSON,
duplicate JSON members, non-finite numbers, wrong session IDs, and EOF without
`done` refuse. Deltas are provisional, not an authoritative answer. Never
redispatch inference or open a network connection.

Adapters expose no credentials, networking, model fallback, or implicit mocks.
The caller explicitly injects the fixture transport.

## Transactional store

`StateError`, `ConflictError(StateError)`, and `NotFoundError(StateError)` are
explicit errors. `Store(path)` opens a private local SQLite file, supports
`close()` and context management, validates schema version, and never silently
resets corruption or an unknown schema. It does not call core code or providers.

`reserve_chat(owner, user_input, session_id=None, idempotency_key=None)` returns
a frozen `ChatReservation(turn_id, session_id, state, response, created)`.
`response` is a normalized JSON object or `None`.

- Authenticate outside the store; `owner` is a trusted storage namespace, never
  model text. The harness derives this private operational partition from both
  authenticated owner and selected workspace. Its lookup digest is not a
  RAPPID, canonical content address, anonymization, or authority grant.
- Explicit-session replay keys are `(owner, session_id, idempotency_key)`.
- No-session replay keys are `(owner, omitted-session, idempotency_key)`; the
  originally allocated response session is retained.
- Terminal chat repeats replay the original retained response even when input
  changes. A repeat pending key returns that same reservation, not a new run.
- Different owners never share replay or session state. A session allocated to
  one owner cannot be adopted by another.
- Without a key, each authorized request is new. Only one active turn per
  owner/session is allowed; conflicting active input refuses.

`mark_chat_running(owner, turn_id)` changes reserved -> running exactly once.
`finish_chat(owner, turn_id, state, response=None)` accepts a terminal state
(`succeeded`, `failed`, `uncertain`, `cancelled`). Success requires an exact
normalized response with the matching session. Terminal records are immutable.
`history(owner, session_id)` returns successful user/assistant messages only.

`admit_job(owner, key, request)` returns a frozen
`JobReservation(job_id, state, request, result, created)`.
Same key + equal request returns the existing job; changed request conflicts.
Use deterministic storage/comparison JSON, explicitly **not** RAPP
canonicalization or a RAPP content address.

`transition_job(owner, job_id, expected, new_state, result=None)` performs a
compare-and-set transition: accepted -> running/cancelled; running ->
succeeded/failed/uncertain/cancelled. Terminal states never reopen.
`get_job(owner, job_id)` returns `JobReservation(created=False)` or refuses.

`recover_interrupted()` is an explicit exclusive-supervisor operation that
marks running chats/jobs uncertain; it never replays tools or inference.
Reserved/accepted-but-not-started entries remain distinguishable. Opening a
store must not invoke recovery automatically while another worker may run.

`store_grant(grant_id, binding)`, `get_grant(grant_id)`, and
`revoke_grant(grant_id)` persist synthetic grants. Bindings are JSON objects;
`get_grant` returns the binding plus boolean `revoked`, or `None`. Unknown or
duplicate grants are explicit errors for mutation; revocation is idempotent.
The policy layer validates every binding field and the clock on each use.

The database is an operational fixture store. It does not mint RAPPIDs, signs,
frame hashes, Work receipts, or native acceptance. A production RAPP frame
writer must later use the selected authenticated canonical SDK contract.

## Offline policy and harness

Synthetic grants bind owner, workspace, session, turn, worker, worker generation,
capabilities, and expiry. Store only random opaque handles for this fixture
protocol. These are not RAPP identities or production bearer credentials.
Model-provided fields cannot widen a grant. Revocation persists across restart.

The harness reserves before invoking an explicitly injected fixture transport.
It replays completed turns, refuses concurrent dispatch, normalizes actual
transport output, and records uncertainty after an interrupted running turn.
The fixture tool writes only within its explicit temporary workspace and
records a separate job result. Same-job retries do not repeat a successful
effect. A file write is not magically atomic with SQLite: if a failure happens
between effect and result, recovery must preserve uncertainty.

The CLI may run synthetic demonstrations and emit evidence with
`stage: "offline-contract-verified"` and `real_grail_executed: false`.
Never turn fixture results into M0 qualification, a sandbox claim, or an
unqualified `passed: true` for the complete product.

## Outside this harness

Real Grail request capture, private OS, network and credential boundaries,
tool-backed inference and cancellation of real process trees belong to the cell
(`cell.md`) and are proved by its own real-core and live tests. Fixture success
here is not proof of those behaviors. Provider independence and native RAPP
evidence are out of scope.
